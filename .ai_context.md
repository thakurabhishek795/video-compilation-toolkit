# AI Context & Instructions

If you are an AI coding assistant (like Cursor, Cline, or DeepSeek) reading this file, please adhere to the following architectural constraints and instructions for the **Video Compilation Toolkit**.

## Tech Stack
- **Frontend:** Streamlit (`app.py`). Use `st.session_state` heavily for maintaining the editing queue (`st.session_state.clips`) and the storyboard.
- **Backend:** Python 3.9+ (`core.py`).
- **Core Processing:** `ffmpeg-python` or direct `subprocess.run(['ffmpeg', ...])`. Always ensure we normalize to `1920x1080` at `25fps` for any compilation tasks.
- **AI Integration:** Local Ollama (`http://localhost:11434`). We primarily query `moondream` (vision) or `deepseek-coder-v2` (text/JSON generation).

## Workflow Rules
1. **Never modify `app.py` logic without checking `core.py`.** The frontend is extremely tightly coupled to the backend data structures. 
2. **Review the Docs:** Before adding massive new features, please review:
   - `docs/ARCHITECTURE.md` (for the structural layout)
   - `docs/ROADMAP.md` (to see if the feature is already planned or partially implemented)
3. **Pipelines:** Complex AI logic belongs in sub-directories like `audio/` or `vision/`. Do not clutter `core.py` with massive ML pipeline classes. `core.py` should only act as a routing and file-management wrapper.
4. **Error Handling:** Streamlit does not crash gracefully. Ensure all calls to `core.py` or sub-pipelines are wrapped in `try/except` blocks in `app.py`, using `st.error(str(e))` to display issues to the user.

## Running the App
```bash
source venv/bin/activate
streamlit run app.py
```
